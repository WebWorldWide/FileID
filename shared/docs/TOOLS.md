# File tools: supported exports and recovery

Tools use typed IPC requests; v1.4 adds the video recipe; v1.9 adds optional conventional photo enlargement. Preview resolves an exact catalog selection, fingerprints source bytes with SHA-256, reserves collision-safe output names, and stores an immutable operation plan. Execute uses that saved plan, checks sources and chapter snapshots again, stages each output, validates it, and publishes with a non-overwriting hard link. The original is never mutated. This requires an output filesystem that supports hard links; unsupported publication fails explicitly.

| Adapter | Inputs | Outputs | Limits and behavior |
|---|---|---|---|
| macOS ImageIO worker | Single-image PNG, JPEG, TIFF, HEIC | PNG, JPEG, TIFF | Orientation applied; maximum dimension 1–8192; downsize by default; opt-in `allowUpscale` enlarges smaller photos using high-quality system interpolation; 8-bit SDR. Color space carried through when supported; camera/location metadata stripped. JPEG alpha flattened onto white. Native worker has a 30-second limit and supports cancellation/parent-death termination. |
| Rust image-rs | Single-image PNG, JPEG | PNG, JPEG, TIFF | EXIF orientation applied; downsize by default, opt-in enlargement uses Lanczos3 with the same 1–8192 bound; APNG rejected; input at most 32 megapixels and bounded decode allocation. Embedded ICC inputs are rejected until color-managed conversion is added. Private metadata stripped; 8-bit output. JPEG alpha flattened onto white. This adapter currently runs decoders in-process and cannot cancel a running export. |
| macOS AVFoundation worker | Self-contained SDR MP4, MOV, M4V with one video and at most one audio track | MP4 H.264/AAC | Native 1280/1920 long-edge presets; portrait orientation retained. Reject HDR, alpha, subtitle/metadata/auxiliary tracks, protected media, durations over six hours and oversized frames. Reopen staged outputs to verify timing, stream count, codecs, dimensions and aspect. Strip camera/location container metadata. Probe limit 20 seconds; export limit one hour; cancellation/parent-death terminate the worker. |
| Both chapter adapters | Current non-stale catalog markers | JSON, WebVTT | JSON retains marker provenance. WebVTT contains chapter cues, not speech transcripts. Cue text is escaped and zero-duration markers receive a 1 ms interval. |

No AI enhancement is implied by resize or conversion. RAW development, HDR-preserving conversion, HEIC output, portable video workers, audio-only tools, trim/remux/proxies, stabilization, AI upscaling, tracked reframing, subtitles from speech, FCPXML, and the broad document/archive/data/ebook/CAD toolbox remain in the implementation ledger. Capabilities describe the adapter actually running; they do not promise every format pair on every OS.

## History and Undo

Every output enters the catalog with an original/export relationship and its recipe. Completed receipts, output hashes, staging paths, and derived catalog IDs are journaled. History survives restart and engine changes, including undone exports and their recovery paths. Completed, failed, and undone plans require a fresh preview before another execution. Undo checks all remaining exports before moving them into `ExportRecovery/<operation-id>` beside the internal catalog; edited exports are left untouched. Recovery paths are shown to the user, so Undo does not permanently delete generated files. Moving an export across filesystems can fail on the Rust adapter; the original remains untouched and the operation journal remains available.

Interrupted exports become failed operations instead of replaying a possibly ambiguous write. Registered staging files are cleaned after a short parent-worker grace period. Cleanup requires an owned UUID filename, the recorded output directory, a regular file, and a writable unprotected location; it preserves unrelated files and aliases. A crash between filesystem publication and receipt acknowledgement can leave a prepared output for manual review. General batch restart/resume and a fully reconciled publication journal remain release gates.

The native macOS File Tools window is accessible from the existing toolbar. It supports catalog search, multi-selection, recipe/output-folder selection, exact preview, export, cancellation, persistent last-operation history, and Undo. Closing and reopening Tools retains its session, and closing the main window does not terminate an active engine. Recipe and source controls are disabled while a tool request is pending. Native WinUI and GTK File Tools dialogs now route search, multi-selection, capability-driven recipe controls, folder picking, preview, export, history, and Undo through the existing engine. They hide unavailable adapters and invalidate saved previews when inputs change. GTK unsubscribes its event task on dialog close; Windows detaches engine listeners. Windows controls are API/type checked against WinUI/SDK metadata with stand-ins for generated XAML fields and service facades; this is not a full app build or runtime claim. The GTK app compiles and passes strict Clippy and 38 tests on the Mac development host; its actual internal-fixture search/enlargement/Undo flow was exercised through native GTK widgets and the real Rust engine. Linux-host behavior remains unverified. The portable decoder isolation/cancellation and full toolbox remain open.

Adlon and managed media-library originals are protected before any output is created, including alias and missing destination checks. Modification and interoperability tests use internal temporary directories only. No new application dependency or model weight was introduced: ImageIO/CoreGraphics are system frameworks, and Rust uses the already locked image-rs and SHA-256 crates.

## Native video export verification

Rights-clear generated portrait footage and a generated tone exercise actual child-worker probing/export, H.264/AAC, audio/video timing, orientation, metadata stripping, source hashes, derivative registration and Undo. Explicit MP4 MIME hints permit validation while the owned output still has its .part staging name. AVURLAsset reference restrictions forbid all external media references, including network and other local files. The new subprocess module is source-digest pinned after review; it invokes only the engine's typed local worker. Rust reports video unavailable and rejects saved macOS video plans before any output/state mutation, rather than treating an unknown recipe as chapter text.

Apple documents these presets as H.264/AAC exports: https://developer.apple.com/documentation/avfoundation/avassetexportpreset1920x1080. No FFmpeg binary, model weight or new package is added; this uses the operating system framework. Codec/distribution checks remain release-specific. Full color/fidelity matrices, unusual audio offsets, HDR-preserving export, resumable batches and native port parity remain gates.

## Conventional enlargement verification

Omitted/false `allowUpscale` preserves existing small-image dimensions. True fills the requested long-edge bound while preserving aspect and orientation; it does not recover missing details or implement neural enhancement. The macOS worker accepts both the legacy four-argument invocation and the bounded five-argument flag. Shared recipe DTOs mirror the optional boolean in Swift/Rust/C#. Other tools reject true before execution. Tests verify input hashes, PNG/JPEG/TIFF output geometry, protected destinations, collision handling, derivative recipes, and recovery history. Actual saved Swift and Rust plans execute across engine changes, including enlargement and persistent Undo.

For isolated GTK QA on this Mac, stage both the app and engine under `/tmp`; loading the engine from the Desktop checkout stalled in dyld before its entry point. Copying the same built executable to internal scratch storage resolved startup without a client-code change. This is a development-host observation, not a Linux diagnosis.
