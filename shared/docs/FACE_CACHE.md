# Face cache provenance and refresh

The v22 migration preserves existing People, face rows, corrections and legacy embeddings. It adds nullable embedding_model, processing_version and source_revision columns; legacy vectors remain unverified rather than acquiring a guessed current-model label.

Native SFace and portable SFace fingerprint the selected ONNX weight file at load. Native processing uses macos-landmark-overlap-v3-orientation or the explicit bbox fallback version; portable image-rs scan and refresh results use rust-landmark-overlap-v2-orientation, while unverified HEIC/video scan decoders retain rust-align112-v1. Native refresh selects missing, malformed or outdated caches in successive batches of at most 5,000 faces, retaining the existing skip/cancellation guards and four-file extraction limit. It checks source size, modification time and file identity before/after decoding/inference and verifies the database snapshot and bbox before saving. It preserves person assignments and ignored faces. JPEG encoding occurs off the database writer; only committed results publish atomic internal cache replacements.

Canonical SQL produces catalog observations and model-separated 128-d vectors, with confidence zero because face quality is not calibrated identity confidence. Person changes synchronize observation membership. Ignoring a face marks generated evidence stale; unignoring cannot revive evidence whose source revision has changed. Changing a bbox invalidates its old vector. Removing a face deletes generated observations/vectors but retains stale manually edited observations. Processing refresh does not overwrite manual markers.

New portable bboxes carry explicit pixel coordinate space and decoded source dimensions, so native thumbnail decoding cannot accidentally normalize coordinates against a smaller image. Legacy dimensionless pixel boxes retain the historical fallback; repair requires source-aware reanalysis rather than guessed scaling.

Tests cover source identity changes, malformed/nonfinite/zero vectors, database/source/bbox/exclusion races, confirmed-name preservation, model-separated catalog records, assignment updates, ignored/stale evidence and manual-marker deletion survival. The actual Swift → Rust → Swift catalog round trip also retains face vectors/provenance/identities/manual markers. These are synthetic correctness tests, not recognition accuracy measurements.

Native clustering retains its conservative selected-space whole-pass guard. Portable clustering instead selects one current model/processing/file-stat partition and reports the active nonparticipants as deferred. No cross-space vector comparison occurs. Participants are reread at commit with source, bbox, ownership and vector checks, while late names and correction verdicts are read inside persistence. Deferred/ignored assignments and confirmed IDs remain, including explicit positive correction links; contradictory correction ownership aborts the transaction. Safe automatic merge suggestions use compatible in-person representatives or deterministic eligible fallbacks, under one read snapshot. Unversioned stored centroids cannot establish identity inheritance. These guards do not establish held-out accuracy or identity-safe existing-library rescans.

## Remaining acceptance work

Portable grouping now isolates compatible participants and reports deferred coverage, but new-only incremental assignment, native Mac partition parity, explicit retry/backlog controls, video tracking, trusted exemplars, held-out calibration, full correction UI parity and general inference isolation remain required. Native refresh advances through bounded batches and records durable retry eligibility; portable refresh also executes that state. Same-size/same-mtime replacement detection and actual identity-safe rescans are separate gates. The legacy mobileclip_s2 label must not be relabeled as verified ViT-B/32 evidence.

Do not erase identities or silently full-recluster to upgrade the cache. Implement incremental namespace isolation and durable refresh with correction preservation before claiming existing-library accuracy improvement.

## Native refresh retry state (v24)

The additive `face_refresh_failures` table stores the latest failed input snapshot, attempt count, coarse reason, and next eligible time. It does not exclude a face, change People, or claim a recognition confidence. Batches advance by face ID during one refresh; a later invocation resumes from stale caches and persisted retry eligibility. Cancellation preserves committed work and leaves unfinished inputs eligible. Changing a source's path/size/mtime, bounding box, or model/processing namespace invalidates the old delay. Successful refresh clears its record. Same-size/same-mtime replacement detection remains a separate limitation.

Existing engines that refuse unknown migration IDs need their matching v24 build. Rollback should retain the database and restore compatible code; no downgrade, graph reset, or destructive contraction is performed. The Rust migration preserves this state for database interchange. Portable refresh now uses it; its progress/coverage interface remains pending.

## Imported box orientation

Native refresh carries the source EXIF orientation alongside ImageIO's transformed pixels. Explicit raw-pixel boxes are transformed into the same upright coordinate system before landmark matching or fallback cropping; native normalized boxes already describe upright pixels and pass through unchanged. Processing version v3 makes older native caches eligible for safe refresh. Rotated legacy pixel boxes without explicit source dimensions are deferred instead of guessing their scale. Tests encode and decode actual JPEGs under all eight EXIF orientations and verify the selected crop region. Portable existing-row refresh now uses upright pixels. Portable image-rs new scans now use upright inference and inverse-transform boxes into raw source coordinates. Held-out face accuracy remains pending.

## People card crop and refresh identity

People thumbnails now map explicit imported raw-pixel boxes through the source EXIF orientation before cropping QuickLook's upright pixels. Native normalized boxes remain upright. Missing orientation metadata and ambiguous rotated legacy boxes fall back to the complete thumbnail instead of guessing. The metadata read uses the existing bounded thumbnail gate and does not modify the source.

Cards reload when the representative face, source path, bbox, model/processing/source revision, or catalog size/mtime changes. The optional thumbnail memory-cache revision prevents a previously cached image from surviving that refresh; the disk cache retains its existing source-metadata key. This fixes display geometry and invalidation, not recognition precision or same-size/same-mtime replacement detection. Generated JPEG tests cover all eight EXIF orientations, native normalized boxes, unavailable sources, source preservation, and stable confirmed identities across refreshes.

GTK's fallback now applies embedded orientation before using the same raw-versus-upright coordinate rules. It reads model/processing/source provenance into its representative cache key. A pure Rust library helper makes the coordinate contract available to native clients; new image-rs scan inference is upright. Saved crops remain the preferred path, and a known decoded extent above 50 MP is rejected before full loading. The portable refresh worker now adds bounded descriptor-checked decoding for existing rows.

Windows refresh keys include representative geometry/provenance and saved-crop metadata. A changed key replaces the card image and bypasses WinUI's URI image cache; unchanged cards remain stable. The People query counts only active faces and chooses an active representative in the same person. The actual query and collection/selection code are tested separately from native WinUI runtime rendering, which still requires Windows.

## Portable refresh execution

People grouping refreshes eligible existing rows in pages of at most 5,000 under `rust-landmark-overlap-v2-orientation`, using the selected registered YuNet/SFace weights. Each file is opened once per page, checked against catalog size/mtime/file identity, decoded within 50 MP and allocation limits, and transformed upright before bounded matching/alignment or bbox fallback. Explicit imported boxes must agree with decoded raw dimensions; ambiguous rotated legacy boxes are deferred. Malformed embedding blobs are rejected at the SQL boundary before materialization. Descriptor/path identity and the catalog/bbox snapshot are checked again before persistence. Encoding/staging occur outside the writer lock, and staged artifacts clean up on cancellation or failed publication.

Failures are durable, source/model/processing/bbox-scoped, and retried with 60-second exponential delays capped at one hour. Changes to path, size/mtime, bbox, model or processing version bypass old delays; successful refresh removes failure state. Cancellation preserves confirmed assignments and stops remaining work. Grouping defers incompatible evidence and revalidates only compatible participants before committing assignments. Scan/deep-analysis admission excludes active People work. Existing raw scan vectors keep `rust-align112-v1`; refresh does not discover faces absent from that scan. Generated fixtures verify geometry and transactional guards through an injected backend. Actual ONNX inference, native hardware, HEIC/video support, same-stat replacement detection and visible backlog/retry controls remain separate acceptance gates.

## Upright scan and publication checkpoint

Decoded image-rs frames retain raw dimensions and EXIF orientation alongside upright pixels. Detected boxes are inverse-transformed before serialization, so People and refresh do not rotate them twice. The same alignment namespace can be used by direct detections and refresh matches; unverified platform HEIC/video outputs keep v1 instead of acquiring current labels. Healthy current rows and durable delayed failures skip ONNX model loading. Selected-model weight fingerprints are content-scoped without inference startup.

Portable crop publication stages and syncs JPEGs outside the writer, then installs a bounded internal journal of old/new database and crop hashes before moving the previous cache. Normal commit failures restore the old crop or remove an uncommitted replacement. Engine startup reconciles interrupted publications before readiness and model admission: committed evidence retains the verified new crop; rolled-back evidence restores the old crop. Person assignments, corrections and original media are not recovery targets. Malformed journals, symlinks, changed artifacts or unrelated face provenance stop recovery and retain the artifacts for review; legacy rollback files without a journal are left untouched. Actual child-process exit tests exercise preparation, backup, publication and database-commit boundaries, plus idempotent recovery and unsafe-artifact refusal. Power-loss behavior and native Windows filesystem/runtime still require hardware evidence. Existing-library scan replacement of face IDs still needs correction-aware preservation before a rescan can be called identity-safe.
